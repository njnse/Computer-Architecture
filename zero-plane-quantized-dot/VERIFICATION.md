# Executed verification methodology

The Python mathematical reference multiplies signed integers directly. A separate bit decomposition is exhaustively checked for W=4 single-lane operand pairs and randomized multi-lane groups. The RTL testbench independently recomputes each accepted group's dot with integer multiplication, checks the Python expected value, then queues that expectation and tag. Results are compared at output handshakes. It checks stalled-output validity/data/tag stability, unsolicited outputs, order, and reset cancellation. Testbench sampling occurs after DUT active-region input capture and before nonblocking updates to avoid a clock-edge race.

Six mechanisms execute matched input groups: parallel, fixed serial, leading-only serial, union-bitmap zero-plane serial, bitmap contiguous-span serial, and the separately implemented counter-based contiguous-span baseline. Widths 4 and 8 and lane counts 1,4,8 are exercised. Continuous tests use six input distributions and independent seeds 7,31,97. Protocol stress uses seed 4242, periodic one-in-eight receiver readiness and randomized producer/receiver pauses, with reset while active and while holding output. The driver obeys input hold requirements until a handshake; reset may cancel a stalled offered input. There are no unverified asynchronous-clock or AXI claims.

Under continuous traffic, **every result latency and the complete input-admission interval sum** are independently checked against direct Python bit count/bit span, including zero groups. This cross-check is not a second cycle model of the RTL state machine. Longer 4,096-group streams use seed 2718 for input generation (ready is continuous; its driver seed does not affect traffic) and check startup/drain accounting. All signed W=4 single-lane operand pairs are also executed in every mechanism. Generic synthesized netlists are re-simulated with reset and randomized backpressure at both main widths. Logical Xilinx netlists receive Yosys structural `check -assert` and retained resource-type audits, but no vendor primitive timing simulation.

Actual public replay executes all 360 held-out images, ten class outputs and sixteen four-feature blocks: 57,600 block outputs per configuration, two widths, two fixed seed-7 checkpoints and six mechanisms. Every block matches the independent integer reference, and summed dot matrices match NumPy integer matrix multiplication. The classification step is host reduction/scaling/bias, not RTL inference. One candidate block-output CSV is checked in, and all run metrics plus stimulus/output hashes are retained. Other raw intermediate block CSVs are regenerated under `build/` by the one-command runner.

Mutation gates insert wrong sign-plane subtraction and acceptance while output is stalled. Both must fail. The initial random-ready mutation escape and the stronger directed test are recorded in DEVELOPMENT.md. This prevents interpreting a passing random test as complete protocol coverage.

Six SAT checks use actual RTL at W=3,N=1 for 12 steps, arbitrary inputs, ready and synchronous reset, and zero initialized state. They assert outstanding-work validity, numeric output and tags. These are bounded reduced-parameter checks, not an unbounded proof of all widths or liveness. Full parameterization proof, formal liveness with fairness assumptions, reset-domain analysis, CDC/RDC, equivalence signoff and fault-injection coverage remain outside this artifact.

This is a validated plain-SystemVerilog/Python environment, **not UVM**. A production UVM extension would use reusable agents, constrained sequences, monitor-driven scoreboard, assertion and functional-coverage closure on a compatible simulator. No unexecuted UVM files are included as validation evidence.
